# نوفا — واجهة طلبات استضافة وإدارة تجريبية

## النشر على Railway
1. ارفع الملفات المستخرجة (server.py وindex.html وadmin.html) إلى جذر مستودع GitHub. لا ترفع ملف ZIP وحده.
2. أمر التشغيل: `python server.py`.
3. في Railway > Variables أضف `ADMIN_USERNAME` بقيمة مثل `admin`، و`ADMIN_PASSWORD` بكلمة سر قوية من 12 حرفاً على الأقل. لا تضعها في GitHub ولا ترسلها لأحد.
4. افتح رابط Railway وأضف `/admin` لتسجيل الدخول.
5. للتخزين الدائم: أضف Volume للخدمة في Railway وحدد مسار الربط مثلاً `/data`، ثم أضف متغير `NOVA_DATA_DIR=/data`. هذا ضروري للحفاظ على الطلبات والمواقع بعد إعادة النشر وقد يكون مدفوعاً. تأكد من إعداد النسخ الاحتياطي.

## حدود النسخة
الباقات للطلب اليدوي فقط؛ لا توجد مدفوعات أو اشتراكات أو تفعيل تلقائي. رفع المواقع الثابتة متاح للمسؤول فقط؛ لا تعمل PHP ولا Node ولا قواعد بيانات المواقع المستضافة. الواجهة والإدارة والمواقع المرفوعة على نفس النطاق؛ ارفع فقط ملفات تثق بها تماماً، فالملفات الخبيثة يمكنها مهاجمة الإدارة. قبل الاستخدام العام يلزم عزل نطاقات المواقع، وحماية من هجمات الدخول والطلبات، ونظام نسخ احتياطية ومراجعة أمنية. الخدمة ليست منصة استضافة إنتاجية متعددة المستخدمين. لا تضع فيها بيانات حساسة.
