# نوفا — نسخة تجريبية

## التحديث على Railway
1. فك ضغط الملف وارفع الملفات المستخرجة إلى جذر مستودع GitHub بدل الملفات القديمة. احتفظ بنسخة من البيانات قبل إعادة النشر.
2. أمر التشغيل: `python server.py`.
3. إن لم تضبط ADMIN_USERNAME وADMIN_PASSWORD في Railway مسبقاً، الدخول الأول هو nova / nova11. إذا ضبطتهما مسبقاً تستعمل القيم الموجودة في Railway بدلاً من الافتراضية.
4. افتح /admin وغيّر كلمة السر فوراً في إعدادات الأمان. يجب أن تكون الجديدة 12 حرفاً على الأقل. إعدادات كلمة السر الجديدة المحفوظة في قاعدة البيانات تأخذ الأولوية على متغيرات Railway.
5. للحفظ الدائم أضف Railway Volume واربطه بمسار مثل `/data`، ثم اضبط NOVA_DATA_DIR=/data. قد يتطلب اشتراكاً مدفوعاً. عند تفعيل Volume جديد انقل قاعدة البيانات والملفات الموجودة إليه أولاً؛ وإلا ستظهر بيانات جديدة فارغة. النسخ الاحتياطي ضروري.

## تحذيرات
nova11 معلنة وضعيفة؛ أي شخص يصل للموقع قد يتمكن من الدخول وتغيير كلمة المرور قبل صاحب الموقع. غيّرها فوراً أو اضبط ADMIN_PASSWORD قوية وفريدة في Railway قبل النشر. إذا ضاعت قاعدة البيانات أو لم يُربط التخزين الدائم فقد يعود الدخول الافتراضي إن لم تضبط متغيرات البيئة. لا تستخدم النسخة للإنتاج أو بيانات عملاء حقيقية قبل مراجعة أمنية شاملة؛ لا يوجد عزل للمواقع المرفوعة عن نطاق الإدارة، ولا حماية قوية من الهجمات. ارفع فقط ملفات موثوقة. الدفع والتفعيل يدويان، والاستضافة للمواقع الثابتة فقط. حساب العميل يتابع طلباته لكنه لا يرفع موقعه، ولا يوجد استرجاع كلمة مرور أو تحقق بريد.
